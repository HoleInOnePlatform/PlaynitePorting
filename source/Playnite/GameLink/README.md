# Native backend handoff (2026-10-01)

The current contract is [HoleInOneBackend/contracts/CONTRACT.md](../../../../HoleInOneBackend/contracts/CONTRACT.md). `TASK.md` is the current plan; archived prototype notes are history.

Installed games retain Playnite's existing local controller path. Instant play asynchronously creates or resumes a backend session using native user credentials, receives the backend-issued playback address and opens WebView2. The default AWS hosted-link mode uses an official CreateStreamUrl URL; the SDK mode retains short-lived backend signaling tickets. The page handles video/audio/input and signaling only. The native `HoleInOneBackendClient` polls authenticated JSON event replay on .NET Framework 4.6.2/x86, preserves cursor/request/session journals, reports ACKs, and queries authoritative state on reconnect. Global sequence gaps are valid. Candidate observations cannot launch a game. Ready starts one attempt; freeze attestation, current lease, restoration and independent actual run identity must all succeed before commit. Backend commit owns cloud termination. Browser messages have no command path.

`SaveRestoreService` accepts the single manifest file `current_run.save`, bounded size/SHA-256, the supported game MVID, profile/run/checkpoint, generation and known transport mod versions. Absolute drive paths are resolved locally; server paths cannot select a destination. Links and UNC/drive-relative/ADS paths are rejected. Same-volume atomic replacement follows a durable backup/journal. An exclusive receipt lock excludes competing restores; an existing-file handle prevents writes between backup and replacement. Corruption, cancellation, launch failure and unresolved outcomes retain the original backup. Changed or running local saves are never rolled back. `CommitPending` journals reconcile durable server state before recovery; expired, unreachable or replaced attempts remain unresolved for manual recovery.

Native session journals are under `%LOCALAPPDATA%/HoleInOne/native-sessions`, keyed by backend/local game/credential fingerprint. A recovered Preparing/Frozen/Restored attempt is failed on the backend instead of relaunched; an ArtifactReady snapshot may start its current attempt once. A confirmed Committed snapshot may close the view. The snapshot cursor prevents replay of older attempts from superseding the latest. Account changes cancel subscription. Credential rotation currently changes this development account key; a production identity/login adapter must supply stable account identity and token refresh.

GameLoader context is atomically written with current-user ACL under `%LOCALAPPDATA%/HoleInOne/handoff/<attemptId>.json`. A direct child `SlayTheSpire2.exe` gets `HIO_HANDOFF_CONTEXT`. Named pipe `HoleInOne.GameLoader.<attemptId>` validates immutable session/attempt/artifact/generation, random 128-bit nonce, expiry, loaded boolean and actual profile/run/checkpoint. Exact retransmissions receive the same ACK during a bounded grace period. Echoing identifiers cannot establish actual run equality. Existing Steam can restart/relaunch the child and drop environment context; actual Steam/game startup and enabled-mod behavior have not been verified, and timeout never commits or terminates cloud play.

## Development configuration and production blockers

When no valid connection exists, instant play opens a native dialog for the backend origin and issued token. The connection record is current-Windows-user DPAPI encrypted at `%LOCALAPPDATA%/HoleInOne/backend-connection.bin` with a user-only directory ACL; tokens are not prefilled/displayed in the dialog or sent to HTML. Complete `HIO_BACKEND_URL`/`HIO_USER_TOKEN` pairs are optional developer overrides, never mixed with saved credentials from another origin. An origin change cannot send the new token to the old server; auth/network rejection allows editing settings. The Playnite executable does not run Node or read AWS credentials. A backend hosted on the same PC separately uses its Node runtime and server-side AWS credentials. Production IdP login, stable user identity and token refresh remain integration work.

`HoleInOneBackend/tools/start-local.ps1 -ConfigureClient` provisions and runs the local development backend and registers this encrypted native configuration. `GET /v2/capabilities` validates user authorization before session creation; fake reports no video, so instant play explains that AWS server configuration is needed rather than trying to play a fake SDP response. Backend setup is part of this project, not a pre-existing service the user must already have.

Production automatic restoration is disabled until the local account/profile, Godot-globalized save root and Steam Cloud policy can be verified. The inspected game API resolves `user://steam/<actual Steam account>/modded/profileN/saves/current_run.save`; any Loaded/Failed mod enables the modded scope even when `affects_gameplay` is false. See [GameLink save API evidence](../../../../GameLink/SAVE_API_EVIDENCE.md). The transport mods must be enabled in the actual game; the installed MVID is inspected without executing the game assembly.

An explicit **development attestation** is available for fake/controlled experiments: set `HIO_ALLOW_ATTESTED_LOCAL_ADAPTER=1`, then create `%LOCALAPPDATA%/HoleInOne/local-save-adapter.json` containing `adapter: "development-attested"`, `installDirectory`, `steamAccountId`, `profileId`, `isRunningModded: true`, `resolvedRunSavePath` (an independently verified absolute drive path with that account/profile suffix), and `steamCloudDisabled: true`. This is a manual assertion, not proof that Steam Cloud is disabled; never label it production verification. The default rejects missing evidence, other gameplay mods and unsupported builds before changing saves. `GameLinkPoint@v0.4.0` and `GameLoader@v0.5.0` are the only known transport versions.

Backups and journals are retained indefinitely for recovery in this implementation. Automated retention/deletion, a historical attempt-outcome API for superseded attempts and fully automatic preflight remain pending. Do not delete unresolved backups to unblock a retry.

## Validation

`source/Tests/HoleInOne.ContractTests` builds a small .NET462/x86 executable against the built Playnite DLL using `/p:PlayniteOutputDir=<build directory>`. It exercises native event/state isolation, cancellation, stale signals, corruption, backup/rollback, exclusive ownership, changed-save preservation, crash reconciliation and fake HTTP plus actual named pipes. It is a fake server and fake game adapter, not GameLift/game E2E. NUnit `GameLinkHandoffTests` was updated but the entire legacy suite has not been executed.

Desktop and Fullscreen compile; the portable ZIP excludes all PC web/server/mock/hosted configuration, preserves CefSharp/WebView2, Steam/Epic and two GameLoader runtime files. `build/check-stream-webview.ps1 -InputDir <build directory>` verifies initialization/viewport/H.264 only. Live cloud video/audio/input, real same-run continuation, Steam synchronization and desktop/fullscreen UI actions remain unverified.

### Cold startup packaging check

Both application projects build and copy `Playnite.BrowserProcess.exe` and its config. Playnite's general CefSharp initialization uses this custom subprocess; `CefSharp.BrowserSubprocess.exe` alone cannot satisfy it. `build/package-portable.ps1` rejects either missing custom file before producing an archive and omits generated diagnostic logs.

Run `build/check-cef-startup.ps1 -InputDir <build directory>` before packaging. It compiles a temporary x86 probe beside the release DLLs, calls production `CefTools.ConfigureCef`, loads an offscreen HTML page through the custom subprocess and verifies a JavaScript result. The executable/config are removed in finally; isolated cache/logs are retained in DataDir for diagnosis. This catches the observed missing-subprocess startup failure. It does not verify the full application UI or GameLift video.

## Local AWS hosted playback address (2026-10-01)

The local backend can call AWS GameLift Streams and return its hosted playback URL through authenticated `POST /v2/sessions/<sessionId>/ticket`. Native Playnite uses `playUrl`, `playbackMode`, and millisecond `expires`; it no longer invents the page address from a ticket. Media flows directly between WebView2 and GameLift Streams, not through the backend.

`aws-hosted-url` accepts only HTTPS `gameliftstreams.aws.com:443`, `/su-<alphanumeric>/stream`, one nonempty `token` query, no user information or fragment, and a live expiry. `sdk` accepts only the configured backend origin root and a fragment matching the returned ticket, with no query or credentials. Initial playback and SDK reconnection both validate the address. Browser top-level navigation remains confined to the validated playback authority, and native user credentials are never inserted into that address.

`URL_READY` means an unused hosted URL exists; it is not a connected game or local-load success. AWS hosted URLs create a session when used and cannot reconnect an existing session. F5/the retry button therefore shows a native explanation without disconnecting/reloading the hosted page or requesting a second URL. Starting another session requires closing the view and explicitly starting instant play again. SDK reconnection behavior and handoff run-proof/commit rules remain unchanged. A previously failed backend session is closed/reset once during a new explicit launch; no automatic new-session loop runs.

The fake-mode warning identifies test mode rather than the backend being local. AWS credentials and permitted stream group/application configuration belong to the backend; its optional cloud GameLink callback connectivity is separate from playback itself. Hosted-session tracking and same-run handoff require the backend to obtain the actual GameLift session identity; URL issuance alone is not proof of either.
